## D-017 2026-10-31 - "Aura Up!" v1 architecture and contract stubs
**By:** integration-programmer. **Decision:** docs/architecture.md replaced (Candy Factory D-009 superseded by D-011) with the v1 architecture for the GDD in D-015. 37 modules: 19 server services (Data 5: DataService, MonetizationService, ComplianceService, LeaderboardService, TelemetryService; World 2: ZoneService, CharacterService; Gameplay 12 in 4 layers: ActivityService, MultiplierService / RankService, ShopService, PetService, BossService / TapService, RebirthService / IdleService, DuelService, QuestService, RewardService), 13 client controllers (UI 9, Effects 4) and 5 shared modules. Dependencies run one way, Gameplay -> World -> Data, and upward calls use inversion (receipt grant registry, duel tap sink). 20 RemoteEvents (16 C->S, 4 S->C), 0 RemoteFunctions, each with server validation and a per-player token bucket declared in Contracts/Remotes. All purchase prompts are server-side after `RequestPurchase` (FirstWin and next-tier-only gate prompts only; every valid receipt is delivered). The multiplier M is computed and clamped (<= 10,000) on the server and never read by duels. Egg odds are integer weights in EconomyConfig, rolled on the server with pity in the profile. PolicyService is checked on the server, fails closed, and reaches the UI as an attribute. A restricted player's Robux-egg receipt grants a disclosed fixed pet. Coin eggs are policy-gated by default until the owner picks D-016 B-1. The profile is ProfileStore schema v1 with a receipt-id log. Attributes have one writer each. Contracts/Types.luau and Remotes.luau were rewritten; the Candy Factory types were removed. **Why:** an intent-only client and a remote list with a validation rule for each give the smallest exploit surface for a clicker with PvP and paid random items. One-writer attributes and layered modules let 4 programmers work in parallel worktrees. Server-side prompts make the FirstWin and D-016 ladder rules impossible to bypass. Failing closed on policy, plus a default coin-egg gate, keeps us compliant whichever B-1 option the owner picks. **Approved by owner:** n.a. (architecture; prices, odds and B-1 stay at the GDD/monetization gates).
