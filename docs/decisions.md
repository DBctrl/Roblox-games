## D-007 2026-10-31 - Candy Factory Tycoon core design and monetization proposal
**By:** scenarist. **Decision:** GDD v1 (docs/gdd.md): button-path dropper/conveyor/seller tycoon, 6-player servers, one currency (Cash), 10 droppers ($0 to $1.1M), 2 upgrade lines (Faster Gears, Sugar Glaze, 3 levels each), uncapped rebirth costing 6M x 2^(n-1) for +50% additive earnings each; income computed on the server per dropper tick, candy on belts is client-side visual only. Monetization: multiplier ladder as permanent **game passes** x2/x4/x8/x16 at 4/8/16/32 R$, highest owned tier applies (no multiplicative stacking between passes), and donation **developer products** at 5/25/100/500/1,000 R$ with cosmetic-only thank-you rewards. No paid random items, no premium currency, no like/favourite rewards; +10% group bonus pending lawyer. All prices PROPOSED. **Why:** follows owner direction D-002; passes fit a permanent "x2 earnings" reading and need no receipt bookkeeping; highest-tier-applies caps the boost at x16 so the economy stays balanced; server-side income with visual-only candy blocks exploits and keeps physics load low; tuned by simulation for first upgrade < 60 s, first rebirth ~24 min, Rebirth 10 ~9-10 h free; scope fits 4 programmers + builder in ~3 weeks. **Approved by owner:** no (pending GDD approval gate).

## D-008 2026-10-31 - Lawyer rulings on Candy Factory Tycoon GDD
**By:** lawyer. **Decision:** (1) No gameplay reward for joining the Roblox group in v1: drop the +10% group bonus; an optional "join our group for update news" button with no reward is allowed. (2) The shop must hide or disable purchase of any multiplier tier at or below the player's highest owned tier, and every pass description states "does not stack; the highest one you own applies". (3) Recommended (owner decides, monetization gate): Top Donors board shows names and rank only, no Robux amounts, with a player opt-out. **Why:** the current Roblox rules on incentivized engagement could not be verified and a gameplay reward for group joins is the riskier reading; selling a pass with no effect for that buyer is misleading; public spend rankings pressure a 9-14 audience and expose minors' spending. See docs/legal.md. **Approved by owner:** no (pending GDD approval gate).

## D-009 2026-10-31 - Candy Factory Tycoon v1 architecture
**By:** integration-programmer. **Decision:** docs/architecture.md v1: 9 server services (Data: DataService, MonetizationService, LeaderboardService; World: PlotService; Gameplay: IncomeService, PurchaseService, RebirthService, DailyRewardService, BadgeAwardService) and 7 client controllers (UI x4, Effects x3). Server-authoritative economy with a single 1 Hz income loop; candy on belts is client-only and pooled. Pads, gates and the seller rebirth prompt are detected on the server (Touched/ProximityPrompt), so only 5 RemoteEvents exist: RequestRebirth, ClaimDailyReward, SetDonorPrivacy (C->S) and Notify, PlayEffect (S->C). State reaches clients via attributes with exactly one writer each (names in Contracts/Types.luau). Gameplay drives plot visuals only through PlotService.setProgress, so no programmer edits another's folder; shared balance lives in shared/Gameplay/EconomyConfig, map naming in shared/World/PlotLayout. Data via ProfileStore (session locking) behind a DataService API; profile schema v1 includes donor-board opt-out and receipt ids. No group bonus. Only Wally package: ProfileStore (server realm), added in a sprint-1 integration ticket. **Why:** fewest remotes = smallest exploit surface and lowest mobile traffic; session locking prevents duplication/lost saves on server hops; one-writer attributes and one-way module dependencies (Gameplay -> World/Data) keep folders independent for parallel worktrees; applies lawyer rulings D-008. **Approved by owner:** n.a.
